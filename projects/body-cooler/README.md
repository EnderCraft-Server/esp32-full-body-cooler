# body-cooler —— ESP32 全身降温器（背包式）

用 ESP32-S3 主控，通过 8x11 软管循环冰水实现全身散热。冰袋方案，不用 TEC。
**365 隔膜泵是有刷电机，只能整段启停，不能 PWM 平滑调速** —— 固件用
「回差 + 最短启停时间」做间歇控制，本质是**周期以秒/分钟计的慢 PWM**。

```
冰袋 + 500ml 水 -> PET 密封罐 -> 365 泵 -> 8x11 软管（贴身循环）-> 回 PET 罐
                        ^                                    |
                        └──── DS18B20 测水温 / 体表温度 ──────┘
                                        |
                                  ESP32 -> 继电器 -> 泵间歇启停
```

## 接线口述（控制端 + 输入端）

> 本节**不含任何电容**（陶瓷、电解一律不要）。省掉它们的后果写在最后 5.5 小节。

### 5.1 先记三条铁律

**① 共地。** ESP32 的 GND、继电器模块的 GND、降压板的 GND、电池负极，必须是同一个节点。
这是最容易漏的一根线 —— 漏了以后 GPIO 推什么电平对继电器模块都没有意义。
症状就是「说 pump=ON 却不吸合、说 pump=OFF 反而一直转」。
实测手法：万用表通断档量 `ESP32 的 GND 脚` 和 `继电器模块的 GND`，必须 0Ω。

**② 泵的电流路径上只能有保险丝和继电器触点。**

```
电池+ → 5A 保险丝 → 继电器 COM → NO → 泵+ → 泵− → 电池−
```

中间**不能有降压板**，也不能让泵的电流流经信号地。这是上次烧泵烧板的直接原因。
另外泵是有刷电机 = 大电感，**续流二极管必须装**：1N5822 反向并联在泵两端，
**阴极（有环那一端）朝泵+**。不装的话，触点断开的瞬间会有几百伏反峰，几个月的功夫触点就烧出麻点。

**③ 继电器是低电平触发**，而且要用**开漏驱动**。

```
吸合：GPIO5 推低  →  IN = 0V
释放：GPIO5 变高阻 →  IN 由 10k 上拉到模块的 5V
```

**绝对不要在释放时推 3.3V。** 模块 VCC 是 5V，光耦 LED 的阴极接在 IN 上，
IN 停在 3.3V 时 LED 上还有 5 − 3.3 − 1.2 ≈ 0.5V 的压差，微弱电流足以把继电器维持住 ——
表现就是「固件说 pump=OFF，泵却一直转」。固件已经默认开漏（`relay od`），
配上一只 `IN ──[10k]── 模块 VCC(5V)` 就彻底干净。

### 5.2 控制端（ESP32 往外发指令）

控制端一共就 **7 根信号线**，全部是单向输出：

| 信号 | ESP32 引脚 | 去向 | 固件命令 |
|---|---|---|---|
| 水泵继电器 | **GPIO5** | 继电器 1 `IN` | 自动 / `pump on` / `pump off` |
| 备用继电器 1 | GPIO6 | 继电器 2 `IN` | `aux 1 on\|off` |
| 备用继电器 2 | GPIO7 | 继电器 3 `IN` | `aux 2 on\|off` |
| 备用继电器 3 | GPIO15 | 继电器 4 `IN` | `aux 3 on\|off` |
| 备用继电器 4 | GPIO16 | 继电器 5 `IN` | `aux 4 on\|off` |
| 有源蜂鸣器（可选） | GPIO17 | 蜂鸣器 `+` | 报警时自动响 |
| 板载 WS2812 状态灯 | GPIO48 | 不用接线 | 板载 |

**每个继电器模块要接 3 根线**，5 个模块 = 15 根：

```
ESP32 J1 GPIOx ───────────────► 模块 IN
5V_A 轨        ───────────────► 模块 VCC     ← 必须 5V，不是 3V3
GND 轨         ───────────────► 模块 GND
```

**每个模块的 IN 再各加一只 10k 上拉到模块自己的 VCC(5V)** —— 一共 5 只 10k：

```
模块 IN ──[10k]── 模块 VCC
```

> 为什么必须加：ESP32 复位期间 GPIO 是高阻，IN 会悬空。悬空本身对低电平触发模块
> 等于「没电流」，是安全的；但水泵电刷的干扰能把它带偏。有了这只上拉，
> 悬空状态被明确拉到 5V，彻底截止。

| # | 从（元件丝印） | 到（元件丝印） | 备注 |
|---|---|---|---|
| 1 | ESP32 `GPIO5` | 继电器 1 `IN` | 水泵主输出 |
| 2 | ESP32 `5V` | 继电器 1 `VCC` | 见下方 5V 说明 |
| 3 | ESP32 `GND` | 继电器 1 `GND` | |

| 16 ~ 20 | 同上 5 根 | 继电器 4 | `IN` 换 **GPIO15** |

> 更稳的做法是**两条独立 5V 轨**：`5V_A` 只给继电器线圈，`5V_B` 只给 ESP32，
> 各自的 GND 再单点汇到一起 —— 这样继电器吸合的压降不会把 MCU 打复位。
> **泵绝不从降压板取电。**

### 5.3 输入端

输入端分三类：单总线、模拟量、开关量。

#### （1）DS18B20 单总线 —— GPIO4

```
3V3 ──[4.7k]──┬──────────────────────────── GPIO4
              │
            ┌─┴─┬─────┬─────┬─────┐
          [探头1][探头2][探头3][探头4][探头5]      5 个全部并联
            └─┬─┴─────┴─────┴─────┘
              │
             GND
```

每个探头三根线：`VDD → 3V3`、`GND → GND`、`DQ → GPIO4`。
**4.7k 上拉只加一只**，接在总线靠 ESP32 的那一端，而且**上拉到 3V3，不是 5V**。

> 挂上去以后用串口 `scan` 看有几个探头，再用 `map skin_chest 0` 之类把 ROM 绑到角色上
> （`map` 会自动写进 NVS，掉电不丢）。
> 目前手上只有 **3 个防水探头，缺 2 个**，总线上现在只扫到 1 个。

#### （2）电池电压 —— GPIO1（可选，`ENABLE_BATT_SENSE` 默认 0）

```
BAT+ ──[R1 100k]──┬── GPIO1 (ADC1_CH0)
                  │
                [R2 18k]
                  │
                 GND
```

分压比 = (100 + 18) / 18 = **6.556**，12.6V → 1.92V，9.0V → 1.37V。
**必须用 ADC1（GPIO1~10）** —— ESP32-S3 的 ADC2（GPIO11~20）在 WiFi 开启时不可用。

#### （3）水流传感器 —— GPIO10（可选，默认关闭，但★强烈建议装）

```
5V_A ──[2.2k]──┬── 传感器 OUT
               │
             [10k] R1
               │
               ├──────── GPIO10
               │
             [20k] R2
               │
              GND
```

高电平 = 5 × 20 / (2.2 + 10 + 20) = **3.11V**，ESP32-S3 的输入门限是 2.475V，留了余量。
传感器是开集输出，**那只 2.2k 不能省**（只靠传感器内部上拉只有 2.50V，贴着门限）。
接好用万用表量 GPIO10 对 GND 的高电平，**要在 2.8V 以上**。

> **这是防烧泵最有效的一道防线**：泵在转、但 15 秒内读不到水流 → 立刻停泵 + 强制休息。
> 已经烧掉 2 台泵了，有条件优先装这个。

#### （4）开关量 —— 全部是「引脚 — 开关 — GND」，用 MCU 内部上拉

| 信号 | GPIO | 接法 | 有效状态 |
|---|---|---|---|
| 液位开关（浮子簧片） | **GPIO11** | 引脚 — 开关 — GND | 低 = 有水 |
| 漏水检测 | **GPIO18** | 引脚 — 裸铜线A — 2mm间隙 — 裸铜线B — GND | 低 = 遇水 |
| 急停 / 总电源开关 | **GPIO21** | 引脚 — **常闭 NC** 开关 — GND | **高 = 按下或线断** |
| 按键 A / B | 38 / 39 | 引脚 — 轻触开关 — GND | 低 = 按下（固件暂未使用） |

**急停为什么用常闭**：不按时触点闭合到 GND，引脚读低；按下时断开、被上拉拉高。
这样「按下」和「线断了」是同一种结果 —— 失效安全。用常开的话线断了没人知道，急停形同虚设。

> 软件急停依赖单片机活着。**强烈建议把开关的另一组触点串在泵的 12V 硬回路里**，
> 这样即使 MCU 死机，按下去也能物理切断。

### 5.5 省掉电容的代价（知道就行，不拦你）

| 位置 | 原本要加 | 不加会怎样 |
|---|---|---|
| 电池分压 R2 上 | 100nF 陶瓷 | 100k / 18k 的并联阻抗约 15k，对 ESP32 的 ADC 偏高，采样电容充电不足会**读数偏低**。固件已经做 8 次平均 + 用 `analogReadMilliVolts()` 读出厂校准值，够用 |
| 泵接线端子 | 100nF 陶瓷 | 电刷高频噪声没有就近旁路，靠续流二极管 + 两条独立 5V 轨硬扛 |

## 控制逻辑

### 三层保护（优先级从高到低）

1. **安全联锁** —— 可打断最短运行时间，立即停泵：
   体表低于 `skinLow`、水温低于 `waterMin`、读数全部失效、漏水。
   带 1 度回差自动恢复（漏水除外，必须 `clear`）。
2. **最短运行 / 最短停机** —— 保护继电器触点和泵的阀片。
   默认 20 秒 / 30 秒，即每小时最多约 72 次启停。
3. **需求控制** —— 回差启停（默认）或时间比例。

### 为什么不能用 PWM

有刷电机的换向器和电刷在低频 PWM 下会剧烈打火、发热、噪音大，
而且隔膜泵在低速下流量急剧下降、阀片拍打异常。所以只能用整段启停，
靠**时间比例**模拟调速 —— 一个周期几分钟，远大于电机的热时间常数，
电机每次都按额定转速工作，没有任何副作用。

### 状态机

```
STANDBY   待机（总开关关 / 手动强制关）
MONITOR   体表未到开泵阈值，泵停
REST      泵停，但在等最短停机时间结束
PUMPING   泵运行中
FAULT     安全停机（过冷 / 无水 / 传感器失效 / 漏水）
```

### 默认参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `target` | 33.0 度 | 体表目标温度 |
| `band` | 1.0 度 | 回差：33.5 开泵 / 32.5 停泵 |
| `slow` | 30.0 度 | 体表下限，低于则强制停泵 |
| `shigh` | 38.0 度 | 体表上限，高于则报警 |
| `wmin` | 8.0 度 | 水温下限（**建议实测后调到 10 ~ 12**） |
| `wmax` | 32.0 度 | 水温上限，高于则报警（冰袋化了） |
| `mon` / `moff` | 20s / 30s | 最短运行 / 最短停机 |
| `ice` | 8 min | 冰袋有效性评估窗口 |
| `mode` | 0 | 0 = 回差启停，1 = 时间比例 |

设好之后 `savecfg` 保存到 NVS，掉电不丢。

### 自检与报警

| 报警 | 触发条件 |
|---|---|
| `SKIN_HIGH` | 体表 >= 38 度：冷却失效，注意中暑 |
| `SKIN_LOW` | 体表 <= 30 度：**立即停泵** |
| `WATER_LOW` | 出水温 <= 8 度：**立即停泵**，防冷损伤 |
| `WATER_HIGH` | 出水温 >= 32 度：冰袋化了 / 没水 |
| `DRY_RUN` | 泵转了 60 秒以上，最冷点还是不冷：干转 / 气堵 |
| `ICE_MELT` | 连续运行 8 分钟，回水出水温差 < 0.5 度且体表仍热 |
| `NO_SENSOR` / `SENSOR_FAULT` | 探头缺失或读数全废 -> 拒绝自动控温 |
| `LEAK` | 漏水（可选功能） |

## 审查结论：动手前必须先解决的 5 件事

详细内容见 `docs/WIRING-REVIEW.md` 和 `docs/SEALING-REVIEW.md`。

1. **泵两端加续流二极管**（1N5408，阴极接 +12V）。
   不加的话，触点拉弧会缩短继电器寿命，反峰还会让 ESP32 随机复位。
2. **继电器 IN 加 10k 上拉 / 下拉**，保证上电瞬间泵绝对不转。
3. **暴露段软管套保温棉，罐子套保温套**。
   不保温时暴露段会白白漏掉约 44W 冷量，和体表实际能带走的热量同一量级 —— **续航直接砍半**。
4. **10 米软管裁到 4 ~ 5 米**。8mm 内径 10 米管的内容积约 0.50 升，和水箱一样大。
5. **锂电池加 5A 保险丝 + 3S BMS**，电池和水箱物理隔开，充电时远离水路。

### 关于效果的预期

按 500g 有效冰量估算，系统有效冷量约 214 kJ：

| 状态 | 续航 |
|---|---|
| 静息（带走约 40W） | 约 89 分钟 |
| 活动（带走约 60W，冰消耗更快） | 约 30 ~ 45 分钟 |

**这是「延缓升温 / 局部降温」装备，不是「全身空调」。**
想延长续航，按性价比排序：加保温 > 加大水量 > 加冰量 > 缩短软管。
